# Workstation pitfalls for every agent runtime

This file is part of the agent working agreement in [AGENTS.md](../../AGENTS.md). It records lessons that were first learned in Claude Code sessions and kept only in that runtime's private memory. They apply equally to Codex, Claude Code, and any other agent working in this clone. Each rule names the failure it prevents.

Read it before working in the shared main checkout, running Unity tests or builds, touching the emulator, or removing worktrees.

## Shared checkout and Git

- **Never move HEAD in a worktree another role is using.** In F006 batch 4 a read-only reviewer ran `git checkout --detach <sha>` in the worktree where QA was running Unity. It was the same commit, so nothing broke, but a different sha would have changed files under a running test. Reviewers read with `git show`/`git diff`; QA verifies HEAD and never checks out.
- **`git worktree remove` fails with "Permission denied" while any shell's cwd is inside the worktree.** The registration is removed but an empty folder stays. `cd` out first; remove the leftover folder with `rmdir` afterwards.
- **Check the branch right before every commit and push.** Parallel sessions share the main checkout because it holds the only Unity editor slot, and they switch its branch mid-task. A commit once landed on another session's branch and had to be cherry-picked back. Run `git branch --show-current` immediately before `git commit` and `git push`. If the branch drifted, cherry-pick onto the intended branch and reset the other local branch to its remote; never rewrite another session's commits.
- **Give `git worktree add` an absolute path when you use `git -C <dir>`.** A relative target path resolves against `<dir>`, not the current directory. That once nested a new worktree inside a Unity worktree; `git worktree move` fixed it.
- **Guard `cd` into a side worktree.** When a worktree was deleted, a failed `cd` let the following `git switch` run in the main checkout. Chain with `&&` (Bash) or check `Test-Path` first (PowerShell), and verify the worktree still exists at the start of each task.
- **Prefer a separate worktree for documentation or tooling changes** so the main checkout's branch stays with the session that holds the Unity slot.
- **MAQA merges go only through `scripts/maqa-merge.ps1 -Issue <n>`**, which checks the QA gate itself; there is no branch protection on this plan. Use `-DryRun` to see whether an Issue is merge-ready.
- **Re-verify MAQA marker comments after a GitHub error.** In F006 P1 a transient GraphQL error in one chained command dropped both a label edit and the worker-done comment. After any `gh` error, re-read the Issue's labels and its marker comments before the next transition.
- **Run the post-merge steps only after `maqa-merge.ps1` exits 0.** In F006 batch P0 (2026-11-11) a Bash chain ran the closing comment, `gh issue close`, `git worktree remove` and the remote branch delete after the script had refused a conflicting pull request (`REFUSED ... CONFLICTING`). The Issue closed unmerged and the pull request closed with its branch. Recovery: push the commit back to the branch, reopen the Issue and pull request, and delete the false merge comment. Run the merge as its own command, check its exit code and `git merge-base --is-ancestor <commit> origin/main`, and only then start the `merged #N` cleanup. Parallel Issues that touch the same file, such as `tools/art-pipeline/art_pipeline/__main__.py`, conflict after the first merge, so dry-run the second Issue before cleanup.
- **Reserve task IDs against MAQA Issue titles, not only `tasks.md`.** MAQA maps an Issue to its task by the ID in the title across all features, and follow-up Issues may carry IDs that appear in no `tasks.md`. F004's first range T193–T242 collided with Feature 003 follow-up Issues (#307 and others) and had to be renumbered. Check `gh issue list --label maqa --state all --limit 500 --json title` before choosing a range.
- **When the runtime refuses a merge or a branch/worktree deletion,** do not work around it. Finish everything else and hand the user the exact commands. Network `git`/`gh` commands handed to the user need the proxy variables cleared, per [github-cli.md](../integrations/github-cli.md), because the user's shell inherits the broken `127.0.0.1:9` proxy.
- **Delete merged MAQA branches with `git update-ref -d`.** `git branch -d` checks against the main checkout's HEAD, which is often another branch, so it refuses a branch that is already merged. After `git merge-base --is-ancestor <branch> origin/main` succeeds, run `git update-ref -d refs/heads/<branch>`.
- **Quote the heredoc delimiter in Bash.** An unquoted `<<EOF` expands backticks and `$` in issue comments and PR bodies, so code spans vanish or run. Write `<<'EOF'`.

## Unity editor slot and scenes

- **Only one Unity editor runs on this workstation**, on the main checkout. The Issue that holds the `unity` lease has its branch checked out there, so Unity MCP sees its code. `scripts/test-unity.ps1` cannot open the main project while that editor is running; use the editor's MCP test runner there, or the CLI in a worktree.
- **Scenes, prefabs, and serialized assets change only through Unity tooling**: Unity MCP on the main-checkout editor, or a temporary `-executeMethod` editor script in a worktree. Never hand-edit scene or prefab YAML to avoid a re-save diff. A one-time serialization migration on the first save, such as new catalog fields written into every entry, is legitimate; report it. QA fails a hand-edited scene diff.

## Unity test runs

- **Unity in batch mode returns immediately from a PowerShell call.** A build or `-executeMethod` started directly as `Unity.exe ... -batchmode` does not block the caller; wait on the Unity process (or use `scripts/test-unity.ps1`, which waits) before reading results.
- **Move, do not copy, a warm `Library/` between sequential Unity worktrees when C: is low.** A Library is about 13 GB; in F006 batch 4 C: had 12 to 13 GB free. Move it from the finished Issue's worktree to the next one before removing the old worktree, and note that it keeps the previous active build target (Android after an APK build).
- **A usage limit can cut a worker or QA agent mid-run.** Check the worktree and the newest `test-results/unity/*` XML first; if the suites finished, do not re-run them. Renew the lease and resume the same agent with its context (SendMessage) instead of starting a new one; a new commit still needs a fresh QA verdict.
- **Synthetic input with scan code 0 is ignored by the Input System.** `keybd_event` with scan code 0 never reaches `Keyboard.current.escapeKey`; only UI Toolkit key events see it. A Play-Tester finding "Escape does nothing" came from that (F006 A-F1). Send real scan codes (`MapVirtualKey`) before filing input defects.
- **A Play Mode result with 0 tests is never a pass.** Through the editor's MCP runner, consecutive Play Mode runs often return `total: 0` ("Passed"), usually every second run, with or without an MCP disconnect. Before each Play Mode run, force a recompile (`CompilationPipeline.RequestScriptCompilation(RequestScriptCompilationOptions.CleanBuildCache)`) and wait until the editor is ready. Edit Mode is unaffected.
- **Run scene suites at a 640x480 Game view.** At 1366 px wide or more, the camera-drag assertion in `CoreGameFoundationSceneTests` fails for layout reasons.
- **A player build leaves the editor's active build target behind.** `BuildPipeline.BuildPlayer` for Android switches the editor to Android, and scene tests then fail with the Android Game view size. In the `finally` of an in-editor build, call `EditorUserBuildSettings.SwitchActiveBuildTarget(BuildTargetGroup.Standalone, BuildTarget.StandaloneWindows64)`. Do not call `PlatformBuildCommands.BuildAndroidArm64DevelopmentGles3` inside the open editor: on failure it calls `EditorApplication.Exit(1)`.
- **Clear the RenderTexture before you capture a UI Toolkit screenshot.** `ShellRig` and the other off-screen rigs render the panel into a `RenderTexture` through `PanelSettings` whose `clearColor` is false, and the shell's world column and safe-area padding draw nothing. Every earlier frame therefore stays visible wherever the final frame is transparent: the first frame before `ApplyScreenLayout` (no safe-area inset, the UXML's default layout class) and the frame before the text scale settled. The result looks like a doubled tab bar, top strip, or zoom column, or a stale tab highlight. The F005 T324 and T359 QA captures (2026-10-14) showed this at 390x844 (100 and 200 %), 640x480 (200 %), and 1024x768. A probe confirmed one `tab-bar` element with correct bounds, and the doubling disappeared once the panel cleared. Before reading pixels, set `rig.Document.panelSettings.clearColor = true` with an opaque `colorClearValue`, right after the rig is created and before its first `Layout()`. Judge layout from `worldBound` and the layout assertions, not from an uncleared capture. The live game is unaffected because the camera clears the screen every frame.
- **A layout change scoped to one screen class and text scale still needs the full Play Mode suite.** Targeted runs and QA without Unity passed F004 T459, but the full suite failed `ContractsAutoDeliverPanelTests` at phone landscape 640x360 and 200 %: a compact-landscape rule narrowed the sheet's horizontal inset from 8 to 6 px, the card got wider and the text wrapped differently. Keep shared horizontal insets when you only need vertical space, and run the full Play Mode suite before handing a layout change to QA.
- **Every Unity CLI run re-creates two noise items in a worktree.** Since F006 P1 (2026-11-12) each `scripts/test-unity.ps1` run re-serialized `ProjectSettings/ProjectSettings.asset` (+130/-1, empty iOS icon slots) and generated an untracked `Assets/UI Toolkit/UnityThemes/UnityDefaultRuntimeTheme.tss` plus `Assets/UI Toolkit.meta`. Restore the first with `git checkout`, delete the second, and never commit either.
- **Reuse an imported `Library/` across sequential Unity Issues.** In F006 P1 the parent moved the merged worktree's `Library/` into the next Issue's fresh worktree with `mv` before `git worktree remove`. The next import was incremental, and the old worktree then removed cleanly without the `\\?\` long-path delete. Do it only when the old worktree is clean and no Unity process uses it.
- **Unity writes packed arrays in YAML.** An `int` or enum array in a ScriptableObject or settings asset can serialize as packed hex with an `i` suffix (`edgeRulePerStage: 000000000100000002000000i`, like `m_StackTraceTypes` in ProjectSettings). That is Unity's own format, not hand-edited YAML.
- **Discard settings noise from test runs and builds.** `scripts/check-settings-noise.ps1` identifies it; restore it with `git checkout` instead of committing it.
- **Since URP (F004 T411), also diff the pipeline assets after Unity runs.** The noise check does not see `Assets/IdleFactory/Rendering/UniversalRenderPipelineGlobalSettings.asset`. Unity has re-serialized it during test runs, once with an emptied `m_Settings.m_SettingsList.m_List`. The URP shader stripping settings live there, and they keep the Android build at 490 instead of 2262 shader variants. Run `git diff` on that asset and on `ProjectSettings/ShaderGraphSettings.asset` after each run. Restore incidental changes with `git checkout`. Never commit them.
- **A full Play Mode run can exceed the 900 s default.** After URP, the full Play Mode suite took 25–30 min in a worktree (F004 T411 QA). Run the full suite with `-TimeoutSeconds 3000`, so that a timeout is not misreported as a failure.
- **Check disk space before an Android build.** Each Unity worktree keeps several GB in `Library/` (about 4.8 GB in `Library/Bee` after one IL2CPP build). In F004 T411, drive C: reached 0 bytes free mid-build (`llvm-objcopy: No space left on device`). Keep at least 20 GB free on C: before an Android build. Remove merged worktrees promptly.
- **The Windows test player can outlive its run.** After `scripts/test-unity.ps1 -StandaloneWindowsPlayer` reports its result, `PlayerWithTests.exe` and `UnityCrashHandler64.exe` under `<worktree>\Temp\UnityTempFile-*` may keep running and lock the worktree. Before deleting such a worktree, list processes whose path lies inside it (`Get-CimInstance Win32_Process`) and stop only those from your own completed run.
- **UI Toolkit drops device pointer events in the batch editor.** Tests that send real pointer input pass or fail differently there, so a real-input test also needs a check in a player.
- **The DevTools test assembly does not run through `scripts/test-unity.ps1`.** It needs `IDLEFACTORY_DEV`: add a temporary `Assets/csc.rsp` that defines it (never commit it), and run with `-assemblyNames IdleFactory.DevToolsTests`.
- **The DevTools assembly needs a direct Unity command line.** `scripts/test-unity.ps1` has no assembly parameter, so T347 called `Unity.exe -runTests -assemblyNames IdleFactory.DevToolsTests` directly (batch mode, its worktree as project) with the temporary `Assets/csc.rsp` in place; see `specs/005-economy-contracts/reviews/full-suite-evidence.md` for the exact command.
- **`File.Replace` onto an existing file fails intermittently on this host.** In F006 P2 (T538, 2026-11-13) about 0.6 % of back-to-back replaces threw `IOException` 0x80070497 (ERROR_UNABLE_TO_REMOVE_REPLACED). The cause is a just-closed handle that an indexer or scanner holds. Production code that replaces files must retry transient IO and access failures for a bounded time; `DisplayPreferencesStore` waits 15, 30 and 60 ms. A test that counts attempts must not let a real `File.Replace` run inside its fault-injecting double, or a genuine host failure adds an attempt. Real-file-system tests assert outcomes only.
- **Finished workers can leave background processes behind** (`python3 -` heredocs, sleep monitors). In F005 batch D, `until grep -q … ; do sleep 20; done` wait loops of a finished worker never ended and locked its worktree; list them by command line and stop only the finished worker's own loops. Before a measurement, run `Get-CimInstance Win32_Process` and look for command lines that contain the worktree path, and stop what is left.
- **`PlayerWithTests.exe` cannot be relaunched standalone.** The test runner deletes it after the run, so quiet-host player timings need a separately built probe player, as in the T300 and T336 measurements.
- **Record host load as a PF-9 deviation.** Name what ran during the timed window (Riot, Steam, Battle.net, Docker, Chrome, other agent sessions) in the measurement record, with approximate load.

## Art tooling

- **The Blender MCP bridge does not run by default.** It answers on `127.0.0.1:9876` only while the Blender GUI is open with the MCP add-on's Auto Start (F004 batch 11, T470). Hold the `gpu` lease, start `blender.exe` from a directory outside the repository, check the bridge with one read-only call such as `get_blendfile_summary_path_info`, and close that Blender instance when the interactive step ends. The final committed render still runs headless.
- **A stale pytest launcher in a worktree venv makes `scripts/test-art-pipeline.ps1` exit 3** ("Failed to canonicalize script path"). Repair it with `uv sync --frozen --offline --reinstall-package pytest --project tools/art-pipeline`, never commit `.venv`, and rerun. Exit 3 is never a pass.

## Emulator and adb

- **The reference emulator's `/data` is nearly full (about 450 to 575 MB free).** Uninstall only `com.DefaultCompany.idlefactorygame` before installing; never clear or uninstall other apps' data and never change the AVD storage threshold without the owner. A development APK built by Unity can carry dead zip data (82 MB file, 46 MB of entries, F006 R-8, carried to T541) and fail `adb install` with `INSUFFICIENT_STORAGE`.
- **Emulator evidence needs exclusive use.** Beyond holding the `emulator` lease, check for foreign `adb`/`monkey` processes and other running sessions before a measurement, verify the installed APK hash and the device checkpoint, and do one unscored launch after an install. Do not run the Unity editor during timed captures. The profiling protocol is in [unity-standalone-profiler-android.md](../integrations/unity-standalone-profiler-android.md).
- **Start the emulator and adb from the main checkout.** An emulator or adb server started from a worktree keeps that directory in use, and the worktree cannot be deleted until `adb -s emulator-5554 emu kill` and `adb kill-server` have run.
- **A long-running emulator degrades** (about 1.5 FPS at full CPU after roughly 12 hours). Cold-boot it with host GPU before measuring.
- **Keep every atlas page at 1 MiB or less (512 x 512 RGBA32).** In F006 (T552, 2026-11-13) the Android GLES3 APK stayed on `SetGameState isLoading: true` for 8+ minutes with `Loading.AsyncRead` at 100 % CPU and no frame once the scene referenced the F004 machines atlas page of 512 x 1024 (2 MiB). Bisect over the first-parent merges from b9221ca: first bad merge T440 (c81f9b1). Removing only the machines atlas, or making it ETC2, loaded in about 3 s; the same sprites as two 1 MiB pages also loaded in about 3 s; storing `assets/bin/Data` uncompressed in the APK changed nothing. `F004SpriteAtlasSettings.MaxPageSize` is now 512, so a family that needs more pixels becomes extra pages of one atlas (machines: 1.0 + 0.25 MiB), and `AtlasPageBudgetTests` checks every shipped page. The root cause inside Unity or the ARM64 translation layer is not identified. `android-emulator-journey.ps1` Launch and ColdRestart now fail when `SetGameState isLoading: false ... label: 0` does not appear within the startup limit, because the graphics device line alone does not prove a playable shell.
- **Never create the game's save folders with `adb shell mkdir`.** A directory under `IdleFactory/Checkpoints` created by the shell user before the app's first run is not writable by the app, which then reports `persistence.failed` ("Checkpoint storage is unavailable"). Launch the app once first, then push fixtures (T351).
- **Computer-use access to a development build is requested by the exe name `IdleFactory.exe`.** Before T340, the DevTools time-scale row covered the Mine control in 16:9 windows (1280×720, 1920×1080), so mouse input could not reach Mine there.

## Leases

- **Release your own leases right after QA or merge.** Nothing releases a lease when a session ends abnormally. Finished Claude Code and Codex sessions have both left live leases behind for hours.
- **A lease whose MAQA Issue is closed is stale.** `scripts/resource-lease.ps1` detects this itself (owner decision 2026-10-10): `-Status` shows it as `STALE (issue closed)`, and `-Acquire` takes it over and reports the previous owner. Leases owned by a session name are not covered; for those, ask the user before releasing one that has not expired.
- **Run `scripts/resource-lease.ps1` from an up-to-date worktree, never by absolute path into the main checkout.** The main checkout often sits on an old branch whose copy of the script predates newer resources. In F004 batch 5 (2026-10-29) a call through the main checkout's copy failed with "Unknown resource 'gpu'", and the chained Unity probe then ran without a recorded lease. Check the exit code of the acquire before starting the guarded work, and do not chain the work after a failed acquire with `;`.

## Shell commands on Windows

- **A refused command has no partial effect.** The command guard refuses an entire PowerShell or shell chain when one part (for example a wildcard `rm` or `Remove-Item`) is blocked, so a backup chained before it never runs. Run backups as their own command, verify them (file count or hashes), and only then run the destructive step. For deletes on the device, list explicit file names instead of wildcards.
- **PowerShell variable names are case-insensitive.** `$a` and `$A` are the same variable; use distinct descriptive names in one-liners.
- **`git worktree move` fails with "Permission denied" while a finished worker's process still uses the worktree.** In F004 batch 12 (2026-11-05) this happened twice: once from an `adb` server and `until grep …; do sleep 20; done` wait loops a worker had started inside the worktree, and once from an orphaned `mcp-for-unity.exe` whose `--pidfile` pointed into that worktree's `Library/MCPForUnity/` after a graphical Editor run had ended. Before moving or removing a reused worktree, list processes whose command line contains the worktree path (`Get-CimInstance Win32_Process`), stop only the finished worker's own leftovers, and kill an `adb` server from the main checkout (`<sdk>\platform-tools\adb.exe kill-server`).
- **Removing a Unity worktree can fail with "Filename too long".** `git worktree remove` unregisters the worktree but leaves `Library/` behind. After confirming the worktree was clean, delete the leftover with `Remove-Item -LiteralPath '\\?\C:\full\path' -Recurse -Force -Confirm:$false` as its own command, with the full `\\?\` path written as one literal string, then run `git worktree prune`. If local `git branch -d` then refuses a merged MAQA branch, verify that its tip is an ancestor of `origin/main` and delete it with `git update-ref -d refs/heads/<branch> <tip>`. Check leftover directories for untracked drafts before deleting them.
