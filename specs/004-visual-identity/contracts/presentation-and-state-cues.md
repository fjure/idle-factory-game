# Contract: Presentation Catalog, State Cues and Animation

**Scope**: spec FR-002, FR-003, FR-010, FR-013–FR-015, FR-019, FR-020, FR-024, US1, US2, US4; research R04–R06, R10, R11.

## Catalog

- Builds on the merged Feature 003 T110 `PresentationSpriteCatalog` (re-validated 2026-10-27): `PresentationSpriteEntry` has `Key`, `Sprite` (frame 0), `FrameCount`, `GetFrame(i)` and an optional `FramesPerSecond`; the catalog offers `Configure`, `Validate`, `IsValid`, `Error`, `TryGet`, `TryGetEntry` and `Get`. Validation today is a hard-coded `Requirements[]` table of the 21 F001 keys that pins world size, pivot **and the literal sprite name**; `F003-*` keys are only checked for a unique key and non-null frames, and failures are strings in `Error`, without diagnostic keys.
- T428 replaces the hard-coded table by a per-key requirement registry (world size, pivot, frame count; no sprite-name pin for primary frames) that covers every key the views use, including the `F003-*` keys, Decision (Architect re-validation 2026-10-27): F001 keys are **not** start-up requirements; no runtime view uses them (the views use `F003-*` keys). They stay legal extra entries in the development catalog and the scene catalog, and their rows move to an optional table used only by `F001AssetContractTests` and `PresentationSpriteCatalogTests`. The fallback frames, `presentation.art.fallback`, `presentation.key.unresolved` and the `F004-` prefix are new in T428.
- Feature 003 keys keep their identifiers and stay the keys that content and views use. Each such entry gains **primary frames** (F004 art) and keeps its F003 placeholder sprite as **retained fallback frames** with the placeholder's own PPU, pivot and world size. New keys (cue icons, body variants, markers) are additive with the prefix `F004-`.
- Start-up validation (T110: world size and pivot) runs on the primary frames; a failing primary set downgrades that key to its retained fallback **only if the fallback itself validates**, logs `presentation.art.fallback` once per key without paths, and the view stays interactive with its cues anchored to the footprint (FR-024). If neither validates, start-up still fails closed with `presentation.key.unresolved`; the Feature 003 failure-matrix tests stay green.
- Fallback is a failure path only, never shipped (SC-003); it is exempt from the crispness rule. Late-loaded art swaps in without layout shift because pivot and world size come from the catalog entry.

## State-cue mapping

- `SlotGridView` maps the **single machine state that `SlotGridModel.BadgeFor(isActive, MachineBlocker, MachinePhase, …)` already resolves** with the Art Bible §6.2 precedence (today it returns the badge keys `F003-BADGE-RUNNING`, `-WAITING`, `-MISSING-INPUT`, `-STORAGE-FULL`, `-PAUSED`, `-INACTIVE`; T429 may make it return a `MachineVisualState` enum with the same precedence, never a second rule) and, separately, the slot condition (empty, locked with level, occupied, selected) to rows of the state-cue set of the Art-Bible-selected variant. It reads only the existing allocation-free presentation states; it adds no gameplay reads and no second precedence rule.
- Exactly one state cue per machine; markers (boosted, Overdrive) are independent. Overlay anchors are fixed relative to the footprint: cue top-right inside the overhang band, marker 1 and marker 2 top-left, selection frame around the footprint.
- Running machines show no state cue. Every other state has a distinct shape cue. Color is never the only difference (FR-010).
- Cue icons, markers and the selection frame render on the overlay sorting layer above all machine art; machine art sorts by slot row; each machine is one Sorting Group (R04). This is new work: today `SlotGridView` uses only `sortingOrder` values (plate 10, machine 100, frame 150, overlay 300), no sorting layers or groups, and its badge and marker anchors are constants for 64 PPU that T429 re-derives for the chosen `D`.
- A cue variant that changes the machine body (variant a) needs a body-state field on `SlotVisual` in addition to `MachineKey` and `Selected`; the body key is chosen from the same resolved state.
- Label text appears only at scales where it meets the minimum text size; the machine panel always names the state.

## Animation

- One shared presentation clock advances every animated entry in a single update: `frame = ⌊t · fps⌋ mod frameCount`, with `t` in integer milliseconds of unscaled presentation time, paused while suspended. No per-machine update, no `Animator`, zero steady-state allocations (FR-026).
- Only running machines animate (`animated = true` in the cue set). Effective reduced motion forces frame 0 for every entry from the next frame (FR-020).

## Display preferences

- Store: `<PersistenceRoots.Resolve(persistentDataPath)>/IdleFactory/Preferences/display-v1.json` (the existing root helper; development subdirectory in the Editor), a sibling of `IdleFactory/Checkpoints/` and `IdleFactory/SessionLog/`, never inside them; no checkpoint or session-log cleanup enumerates it; `{ "version": 1, "reducedMotion": "followSystem" | "on" | "off" }`. Strict token-walk reader (no reflection deserialization), maximum 4 KB, version exactly 1, unknown members and wrong types rejected. Atomic write: temp file in the same directory replaced by a native rename/replace; on failure the prior file stays unchanged and the in-memory choice still applies.
- Missing, unreadable, oversized, unknown version, unknown member or invalid value → `followSystem`, diagnostic `preferences.display.invalid` once per session (a re-read on focus return does not repeat it while the file stays invalid), file rewritten on the next change. Never touches the save directories.
- Re-read: lazily when the Settings sheet opens and on focus gain in `CoreGameFoundationBootstrap.NotifyFocusChanged`, synchronous and bounded by the 4 KB cap, never throwing.
- OS signal: follows the pattern of the existing `ShellTextScale` Android `fontScale` read (JNI inside `#if UNITY_ANDROID` and `try/catch`). `IReducedMotionSignal` implementations live in separate files (`Unity/Bootstrap/ReducedMotionSignal.Android.cs`, `.Windows.cs`, `.Default.cs`); every API failure returns "not reduced" and never throws; the Windows call uses `SetLastError = true` and logs only the error code; the Android JNI access is preserved in `link.xml` with a rationale comment.
- UI: a single-choice radio group "Follow system / On / Off" with a live line naming the current effective state and its source; keyboard reachable with visible focus, at least 44×44 pt, usable at 200 % text, inside the new Settings sheet opened by a gear icon in the HUD (plan OD-8; focus return to the gear on close, Escape/Android Back close the sheet). Mount: a new `ShellPanelIds.Settings = "settings"` (added to `IsKnown`) and an `IShellPanel` implementation registered with `ShellPanelRegistry`; the gear is a new element in the `FactoryRun.uxml` top strip looked up by `RunShellDocument`; closing uses the existing `RunShellDocument.HandleBack`. Opening: `ShowPanel(ShellPanelIds.Settings, ...)` with its own open-state flag; opening Settings replaces an open tab or slot sheet (one sheet host). Closing: `HandleBack` gets a new branch after the dialog and pinned-host cases and before the slot/tab case (Settings open → close Settings, focus returns to the gear); without it Escape/Android Back would not close Settings. Gear placement: last element of the top strip, right-aligned, fixed 44×44 pt and not shrinkable; stat captions ellipsize first; last in focus order after Overdrive; in the landscape side-panel layout it moves with the strip into the world column. The strip may grow at 200 % text; `TryGetUnobstructedScreenRect` already measures the strip, so the camera rect follows without special handling and the layout test checks it per class.
- States of the sheet:

  | State | Radio | Effective line | Note |
  |---|---|---|---|
  | No stored file or invalid file | Follow system | "Following system: reduced motion on" / "... off" | none |
  | System setting unavailable (no OS signal) | Follow system | "Following system: not available, animation plays" (copy changed by T475, owner decision 2026-11-04 on the T433/T455 reviews) | none |
  | User On / User Off | On / Off | "Reduced motion on (your choice)" / "... off (your choice)" | none |
  | Last write failed | the chosen value | as above | "Not saved" text with an icon (not color alone), stays until the next successful write; the next change retries the write |

- Accessibility: the gear has the accessible name "Settings" and a tooltip; the radio group has a group label and exposes the selected state; the effective line is text, never color only. Screen-reader announcements are a platform limit (Feature 005 R-21) and are checked as a TalkBack device pass, not claimed by automated tests. On a write failure the choice stays applied in memory and an inline "Not saved" note appears (no modal).

## Tests

- Edit Mode: `PresentationCatalogFallbackTests` (requirement registry replaces the F001 table; existing `PresentationSpriteCatalogTests` stay green or change only with a listed reason; primary fails → fallback; fallback also fails → `presentation.key.unresolved`; partial atlas; fallback pivot offset; additive keys); `StateCueSetTests` (each `BadgeFor` result → distinct shape key, asserted against `SlotGridModel.BadgeFor`; slot conditions separate); `PresentationAnimationClockTests` (frame formula, only running animates, still states, suspend); reduced-motion resolution matrix; `DisplayPreferencesStoreTests` (valid, missing, truncated, wrong version, unknown value, oversized, read-only directory, atomic-write failure); warmed allocation tests (`GcAllocationCounter`) for clock tick, cue refresh and camera snap.
- Play Mode: fully occupied 12-slot frame with the densest overlay at `n_min`, nothing hidden by overhang, top row not clipped by the HUD; tap on a tall machine's overhang selects the slot behind it; reduced-motion control (focus order, labels, 44 pt, 200 % text) freezes loops; missing-art fallback keeps the slot tappable; save directories byte-identical before and after preference changes. Reduced motion, fallback and allocation checks also run tagged `[Category("StandalonePlayer")]`.
