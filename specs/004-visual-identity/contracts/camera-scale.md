# Contract: Integer Camera Scale

**Scope**: spec FR-011, FR-012, FR-016–FR-018, US3, SC-005; research R02, R03, R15.
**Owner**: `Assets/IdleFactory/Unity/Presentation/FactoryCameraController.cs`. After T427 it is the only code outside tests that writes `orthographicSize`, `orthographic` and the camera transform (QA guard: `git grep -nE "orthographicSize\s*=|\.orthographic\s*=" -- Assets/IdleFactory/Unity` lists only this file). Core is not involved.

**Baseline on `main` (re-validated 2026-10-27)**: zoom is continuous. `FactoryCameraController.ZoomAtWorldPoint` scales `orthographicSize` exponentially and clamps it, and `ZoomFromVisibleControl(±1)` takes one exponential step. Limits come from `RunZoomSettings` in `SlotGridView.cs` (16–64 points per cell, fit-all floor 24). `RunCameraFraming.FitAll` writes `orthographicSize` directly, and `RunCameraFraming.FrameSlot`/`FrameContent` handle the sheet framing. `CoreGameFoundationBootstrap` wires `ConfigureLimits`, `FitAll` and `RunShellDocument.ZoomRequested`. T427 replaces this baseline: `CameraScaleModel` decides size and position, `RunCameraFraming` keeps only the extent and framing geometry and no longer writes the camera, and `RunZoomSettings` stays a serialized type but is reduced to the Art Bible inputs (`readableCellPoints`, `maxScale`), so the scene's serialized `zoomSettings` block needs no hand edit; a re-save through Unity tooling is the only accepted scene change.

## Definitions

- `D`: art pixels per cell (= sprite PPU), from the Art Bible.
- `n`: integer scale, device pixels per art pixel.
- `pxPerPoint`: physical pixels per UI panel point for the current screen: `RunShellDocument.Root.panel.scaledPixelsPerPoint`, the value `ShellPanelScale.Decide` produced for the current `ShellDeviceProfile` (fractional; raised on touch devices with known DPI so that 44 pt ≥ 7 mm).
- `rect`: HUD-aware unobstructed rectangle in physical pixels from `RunShellDocument.TryGetUnobstructedScreenRect(screenHeight, out rect)`. It already excludes the top strip, the detail, notice and hint bars, the zoom column, open sheets and the ore-vein overlay.
- Screen class: `FactoryHudLayout` as chosen by `FactoryHudDocument.Classify` from the panel-point size.

## Rules

1. At rest, `orthographicSize = camera.pixelHeight / (2 · n · D)` and the camera position is a multiple of `1 / (n · D)` world units on both axes (one device pixel). An odd camera pixel width or height offsets that grid by half a **device** pixel, `1 / (2 · n · D)` world units, so every art pixel edge stays on a device pixel edge (half an art pixel would be wrong for `n > 1`).
2. `n_min = ⌈readableCellPoints · pxPerPoint / D − 0.01⌉` (at least 1; the 1 % tolerance is the owner decision of 2026-10-28, so a floor miss under 1 %, such as the 1280x720 phone at 320 dpi with `pxPerPoint` 2.0046 at `D` = 24, is not a violation); `maxScale` from the Art Bible. The allowed set is `[n_min, maxScale]`. `pxPerPoint` and `rect` come from `RunShellDocument` as defined above; the controller receives them through the bootstrap wiring that today passes `CoreGameFoundationBootstrap.PixelsPerPoint()`. `TryGetUnobstructedScreenRect` returns false until the panel layout resolves; until then no re-fit happens, and the first `true` triggers exactly one fit.
3. Fit-all: `n_fit` = the largest `n` in `[n_min, maxScale]` at which the 12-slot extent (`SlotGridLayout`) plus a half-cell margin fits `rect`; the factory is centered and the remaining space is margin. For a supported screen class, no such `n` is a contract violation caught by the table test. At runtime (free desktop windows, continuous `pxPerPoint`) the camera instead uses the largest `n ≥ 1` that fits, ignores the floor and logs `presentation.scale.belowFloor` once per layout; it never uses a fractional scale.
4. Pinch changes a continuous preview; on gesture end it snaps instantly to the nearest allowed `n` (ties toward the larger) while the world point under the gesture anchor stays fixed. Pinch end arrives as a new additive `NavigationIntentKind` member (for example `ZoomGestureEnded`) emitted by `Unity/Input/NavigationGestureInterpreter.cs`/`NavigationInputAdapter.cs` (today they emit only `WorldTap`, `Pan`, `Zoom` and `CancelWorldGesture`; T454 adds it), so the bootstrap's `RouteNavigationIntent` switch stays exhaustive. Wheel and button zoom are single-shot and never produce a preview. Until T454 lands, each pinch `Zoom` intent snaps directly (T427). One wheel notch and one zoom-button press (`ZoomFromVisibleControl`) step by one level. Buttons are disabled with a visible reason at the range ends and hidden when the range has a single level. The preview never persists at rest.
5. A second world touch, rotation or layout change during a gesture cancels it and re-fits only if the current `n` no longer fits.
6. Pan limits are recomputed from `rect` and `n`; panning never shows more than a half-cell margin beyond the factory extent (today's `panPadding` of 1 world unit becomes half a cell).
7. With a bottom sheet open, the selected slot stays fully inside the visible world band: first pan it into the band (pan limits relaxed by the band), then, if it still does not fit, step down to the largest `n ≥ n_min` at which it does. On sheet close the prior `n` and position return unless the player zoomed or panned meanwhile. Changes are instant. With a single-level range (`n_min = n_fit = maxScale` on the worst phone at D = 24), only the pan step applies; if the slot still cannot fit, the slot's footprint is aligned to the band's top edge and the selection frame stays visible (the sheet may cover part of the slot's overhang band, never the footprint). Pinch has no effect in a single-level range and buttons are hidden. This replaces the continuous framing in `RunCameraFraming.FrameSlot`/`FrameContent`.
8. Hit testing is unchanged: footprint only, through `SlotGridLayout.HitTest` / `TryHitSlot`.
9. Camera state is never saved.

## T427 integration notes

- `RunZoomSettings` (`SlotGridView.cs`) now holds only the Art Bible inputs `artPixelsPerCell` (D = 24), `readableCellPoints` (24) and `maxScale` (6); the scene's older serialized `minimumPixelsPerCell`, `maximumPixelsPerCell` and `fitAllFloorPixelsPerCell` entries are dropped by its next re-save through Unity tooling (no hand edit).
- `RunCameraFraming` computes geometry only (`ConfigureLimits`, `FitAll`, `FrameSlot`, `FrameContent`); `FactoryCameraController` is the only code that writes the camera.
- The `+1` world unit of pan slack while a sheet is open is named `SheetRelaxSlackWorld` (one cell: the half-cell margin on both sides of the slot footprint). `CloseSheet` clamps the restored scale to the allowed range and the largest fitting scale, so a layout change while a sheet is open cannot restore a stale scale; `Fit` ends an open sheet without a restore.
- Until T454 each pinch `Zoom` intent below one level accumulates a continuous scale and snaps at once; an intent of at least `0.95` (a wheel notch) steps one level.

## Tests

- Edit Mode `CameraScaleModelTests`: rules 1–7 as pure functions (including gesture cancel and pan limits), fractional `pxPerPoint` values (1.68, 2.0, 2.625, 3.0), odd pixel sizes, free desktop window sizes and the runtime degrade; hit area of at least 44×44 pt for a slot footprint at every allowed `n`.
- Edit Mode `ScreenClassScaleTableTests`: every `FactoryHudLayout` class and orientation × the chosen `D` satisfies `n_fit ≥ n_min`, with the expected level count and margin per class (including 360×640 and 390×844 portrait), emitted as a table into every spike and acceptance record. `pxPerPoint` per row comes from `ShellPanelScale.AuthoredPixelsPerPoint` and, for the touch reference profiles with known DPI, from `ShellPanelScale.Decide`; both values are listed. A Play Mode variant uses the real `TryGetUnobstructedScreenRect` with the worst-case overlays (ore vein, hint bar, open sheet), and a negative case with an oversized HUD must fail.
- Play Mode: re-baselined cases, each with its old-to-new expectation in the QA report (`TheZoomLimitsComeFromTheSettingsAndNotFromLiterals` lives in `SlotGridTests`, not `RunHudLayoutTests`): `SlotGridTests.TheZoomLimitsComeFromTheSettingsAndNotFromLiterals`, `FitAllShowsAllTwelveSlotsReadableAtEveryScreenClass` (today the 24-point floor and a 48 pt slot width), `TheSelectedSlotStaysInViewAboveAnOpenSheet`, `ASheetOpenedOnAPhoneLeavesAWorldBandThatShowsAWholeSlot`; `SlotGridTests.FitAllReproducesTheArtBibleTableAndStaysAboveTheReadableFloor`, `ZoomLimitsAreSettingsWithTheArtBibleDefaults`, `BadgesAndMarkersScaleForTheProjectedSizeAndMarkersHideBelowTheFloor` (invariants kept: 12 slots at fit-all, selected slot above a sheet, minimum cell via `n_min`; the `RunZoomSettings` constants change only here; old-to-new assertion diff in the QA report); a crispness test (research R13 capture method) asserting uniform `n×n` art-pixel blocks at rest, tagged `[Category("StandalonePlayer")]` as well; selection-frame thickness in art pixels at each `n`; a live window resize re-fits only when the current `n` no longer fits.
