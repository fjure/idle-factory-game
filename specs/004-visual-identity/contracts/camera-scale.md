# Contract: Integer Camera Scale

**Scope**: spec FR-011, FR-012, FR-016–FR-018, US3, SC-005; research R02, R03, R15.
**Owner**: `Assets/IdleFactory/Unity/Presentation/FactoryCameraController.cs`, the sole writer of camera size and position after T427. Core is not involved.

**Baseline on `main` (re-validated 2026-10-27)**: zoom is continuous. `FactoryCameraController.ZoomAtWorldPoint` scales `orthographicSize` exponentially and clamps it, and `ZoomFromVisibleControl(±1)` takes one exponential step. Limits come from `RunZoomSettings` in `SlotGridView.cs` (16–64 points per cell, fit-all floor 24). `RunCameraFraming.FitAll` writes `orthographicSize` directly, and `RunCameraFraming.FrameSlot`/`FrameContent` handle the sheet framing. `CoreGameFoundationBootstrap` wires `ConfigureLimits`, `FitAll` and `RunShellDocument.ZoomRequested`. T427 replaces this baseline: `CameraScaleModel` decides size and position, `RunCameraFraming` keeps only the extent and framing geometry and no longer writes the camera, and `RunZoomSettings` is removed or reduced to the Art Bible values.

## Definitions

- `D`: art pixels per cell (= sprite PPU), from the Art Bible.
- `n`: integer scale, device pixels per art pixel.
- `pxPerPoint`: physical pixels per UI panel point for the current screen: `RunShellDocument.Root.panel.scaledPixelsPerPoint`, the value `ShellPanelScale.Decide` produced for the current `ShellDeviceProfile` (fractional; raised on touch devices with known DPI so that 44 pt ≥ 7 mm).
- `rect`: HUD-aware unobstructed rectangle in physical pixels from `RunShellDocument.TryGetUnobstructedScreenRect(screenHeight, out rect)`. It already excludes the top strip, the detail, notice and hint bars, the zoom column, open sheets and the ore-vein overlay.
- Screen class: `FactoryHudLayout` as chosen by `FactoryHudDocument.Classify` from the panel-point size.

## Rules

1. At rest, `orthographicSize = camera.pixelHeight / (2 · n · D)` and the camera position is a multiple of `1 / (n · D)` world units on both axes.
2. `n_min = ⌈readableCellPoints · pxPerPoint / D⌉`; `maxScale` from the Art Bible. The allowed set is `[n_min, maxScale]`. `pxPerPoint` and `rect` come from `RunShellDocument` as defined above; the controller receives them through the bootstrap wiring that today passes `CoreGameFoundationBootstrap.PixelsPerPoint()`. An odd camera pixel width or height offsets the camera by half an art pixel so the grid stays aligned.
3. Fit-all: `n_fit` = the largest `n` in `[n_min, maxScale]` at which the 12-slot extent (`SlotGridLayout`) plus a half-cell margin fits `rect`; the factory is centered and the remaining space is margin. For a supported screen class, no such `n` is a contract violation caught by the table test. At runtime (free desktop windows, continuous `pxPerPoint`) the camera instead uses the largest `n ≥ 1` that fits, ignores the floor and logs `presentation.scale.belowFloor` once per layout; it never uses a fractional scale.
4. Pinch changes a continuous preview; on gesture end it snaps instantly to the nearest allowed `n` (ties toward the larger) while the world point under the gesture anchor stays fixed. Gesture end is detected from the `NavigationIntent` stream of `Unity/Input/NavigationInputAdapter.cs` and `NavigationGestureInterpreter.cs` (today they emit no gesture-end signal; T427 adds it there, presentation-only). One wheel notch and one zoom-button press (`ZoomFromVisibleControl`) step by one level. Buttons are disabled with a visible reason at the range ends and hidden when the range has a single level. The preview never persists at rest.
5. A second world touch, rotation or layout change during a gesture cancels it and re-fits only if the current `n` no longer fits.
6. Pan limits are recomputed from `rect` and `n`; panning never shows more than a half-cell margin beyond the factory extent (today's `panPadding` of 1 world unit becomes half a cell).
7. With a bottom sheet open, the selected slot stays fully inside the visible world band: first pan it into the band (pan limits relaxed by the band), then, if it still does not fit, step down to the largest `n ≥ n_min` at which it does. On sheet close the prior `n` and position return unless the player zoomed or panned meanwhile. Changes are instant. With a single-level range (`n_min = n_fit = maxScale` on the worst phone at D = 24), only the pan step applies; if the slot still cannot fit, the slot's footprint is aligned to the band's top edge and the selection frame stays visible (the sheet may cover part of the slot's overhang band, never the footprint). Pinch has no effect in a single-level range and buttons are hidden. This replaces the continuous framing in `RunCameraFraming.FrameSlot`/`FrameContent`.
8. Hit testing is unchanged: footprint only, through `SlotGridLayout.HitTest` / `TryHitSlot`.
9. Camera state is never saved.

## Tests

- Edit Mode `CameraScaleModelTests`: rules 1–7 as pure functions (including gesture cancel and pan limits), fractional `pxPerPoint` values (1.68, 2.0, 2.625, 3.0), odd pixel sizes, free desktop window sizes and the runtime degrade; hit area of at least 44×44 pt for a slot footprint at every allowed `n`.
- Edit Mode `ScreenClassScaleTableTests`: every `FactoryHudLayout` class and orientation × the chosen `D` satisfies `n_fit ≥ n_min`, with the expected level count and margin per class (including 360×640 and 390×844 portrait), emitted as a table into every spike and acceptance record. `pxPerPoint` per row comes from `ShellPanelScale.AuthoredPixelsPerPoint` and, for the touch reference profiles with known DPI, from `ShellPanelScale.Decide`; both values are listed. A Play Mode variant uses the real `TryGetUnobstructedScreenRect` with the worst-case overlays (ore vein, hint bar, open sheet), and a negative case with an oversized HUD must fail.
- Play Mode: re-baselined zoom, sheet-framing and fit-all-floor cases in `RunHudLayoutTests` and the fit-all case in `SlotGridTests` (invariants kept: 12 slots at fit-all, selected slot above a sheet, minimum cell via `n_min`; the `RunZoomSettings` constants change only here; old-to-new assertion diff in the QA report); a crispness test (research R13 capture method) asserting uniform `n×n` art-pixel blocks at rest, tagged `[Category("StandalonePlayer")]` as well; selection-frame thickness in art pixels at each `n`; a live window resize re-fits only when the current `n` no longer fits.
