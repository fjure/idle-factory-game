# Save V2 fixtures

Generated by `SaveV2FixtureTests.CommittedFixtures_AreByteIdenticalToTheirInMemoryRegeneration` (T104) from `SaveV2Scenarios`, the unchanged Core run domain, `W003Workload` and `SaveV2Mapper`. The test regenerates every file and this README in memory and compares them byte for byte with the committed copies. Drift fails the test; it never skips (OPS-5). To regenerate deliberately, set `IDLEFACTORY_REGENERATE_SAVEV2_FIXTURES=1` and run the test file directly:

```powershell
$env:IDLEFACTORY_REGENERATE_SAVEV2_FIXTURES='1'; scripts/test-unity.ps1 -TestFile Assets/IdleFactory/Tests/EditMode/SaveV2FixtureTests.cs
```

Hashes are SHA-256 over the file bytes. Valid fixtures load and re-serialize to identical bytes. Corrupt fixtures are syntactically valid, structurally complete files that break exactly one cross-field bound of load rule 4 (SEC-2) and are rejected with `save.v2.crossfield`.

Fixtures 01 to 04 load against the test catalog of `SaveV2Scenarios.Options()` (`RunCommandFixtures`); 05 to 07 load against the test-local catalog of `W003Workload`. plan.md, Performance now carries the event bound on W003-B, so W003-B, W003-S and W003-R are all committed; the contract's fixture list names only S and R, and B is the record that carries the SC-008 event bound. W003-S must not be used as that record.

### Shipped-catalog sets (T245)

`device/w003-s` above is generated against the test-local catalog of `W003Workload` (Presses and Assemblers in slots 7 to 11 at factory level 1) and is kept unchanged for the byte-identity test; the shipped content has four slots at factory level 1 and unlocks the Assembler at level 3, so the real player rejects it (`save.v2.invariant`, then `return.blocked`; `DeviceSetShippedCatalogTests` pins this). The two sets below are built against the catalog the player builds with `RunCatalogBuilder` from the frozen revision 2 catalog `Assets/IdleFactory/Tests/EditMode/Fixtures/SaveV2/FrozenCatalog/iron-factory-content-r2.json` (a byte copy of the shipped content at schema version 3, contentRevision 2, taken by T313 so that later content revisions do not invalidate these sets), through the real `RunCommands` from a fresh run, and written through `JsonRunCheckpointStore`. `DeviceSetShippedCatalogTests` regenerates them byte for byte (drift fails, never skips, OPS-5; `IDLEFACTORY_REGENERATE_SAVEV2_FIXTURES=1` rewrites the files, and `SaveV2FixtureTests` rewrites this README) and loads them through the player cold-start path.

Composition:

- `device/w003-s-shipped`: factory level 5 (12 slots), storage level 5 (capacity 16_000), 12 machines: 3 x miner level 25 (cycle 1_314_167 ticks), 4 x smelter level 25 (cycle 1_314_167 ticks), 3 x press level 30 (cycle 1_341_600 ticks), 2 x assembler level 33 (cycle 1_331_257 ticks); auto-sell on iron.bar, iron.gear, iron.ore, iron.plate; 1 Item effect(s), Overdrive active; Cash 4_560_549, stock value 0, Factory Value 5_001_518 (threshold 10_000_000).
- `device/prestige-ready`: factory level 4 (10 slots), storage level 4 (capacity 8_000), 10 machines: 2 x miner level 40 (cycle 1_242_841 ticks), 3 x smelter level 40 (cycle 1_242_841 ticks), 3 x press level 40 (cycle 1_491_410 ticks), 2 x assembler level 40 (cycle 1_242_841 ticks); auto-sell on iron.gear; 0 Item effect(s), Overdrive inactive; Cash 9_341_663, stock value 85, Factory Value 10_006_061 (threshold 10_000_000).

Deviations of `device/w003-s-shipped` from W003-S (`06-w003-s-stress.json`), each forced by the shipped content:

- Catalog: the shipped catalog instead of the test-local one (different Items, machine cost curves, speed growth and milestones, storage and factory tables).
- Factory level 5 (12 slots) reached with 4 `UpgradeFactory` commands (invested 58_720) instead of factory level 1 with twelve slots; storage level 5 (capacity 16_000, invested 212_500) instead of storage level 2.
- Machine levels 25 (Miner, Smelter), 30 (Press) and 33 (Assembler) instead of level 2 with test speed tables. Speed comes from the shipped growth 1.08 per level and the milestones x2 at 10 and 25, which puts the cycles at or near the event bound (`minCycleTicks` 1_000_000) while the Item and Overdrive are active; the exact cycles are listed above.
- The Item effect is `item.overclock-core` (factory, machineSpeed, 120 s) and Overdrive lasts 30 s (shipped values) instead of x2 effects for ten hours. Both expire a few minutes into the eight offline hours, so the reconcile has boundaries that W003-S avoids; this is the shipped content, not a choice.
- The state is the result of commands from a fresh run (Cash 5_000_000 at the start), so the unlock order, invested Cash and a few seconds of production (mid-cycle machines) are the ones the shipped rules produce; W003-S was constructed directly. The inventory holds what the production left (auto-sell empties it).

Deviations of `device/prestige-ready`: it is not a W003 variant. Starting Cash 10_000_000 spent through the commands keeps the Factory Value at the threshold (Cash and invested amounts both count), so the Factory Value only meets it because of the production of the first seconds; the machines are level 40, auto-sell is on Gear only, no Item effect and no Overdrive are active.
